# CHANGELOG

# История изменений интеграции SkyCooker для Home Assistant

Этот файл описывает изменения интеграции `skycooker` между релизами.  
Фактическая версия интеграции указывается в `custom_components/skycooker/manifest.json`.

## v1.3.3 — 2026-08-28

### ✨ Добавлено

- **Недостающие статусы протокола** (все поддерживаемые модели):
  - `4` — «Ожидание загрузки продуктов» (`wait_product`);
  - `7` — «Ошибка» (`error`);
  - `8` — «Ожидание подтверждения» (`wait_confirm`);
  - `9` — «Остановка (потеря питания)» (`stop_power_loss`).
  - Переводы en/ru, fallback в `status.py`.

- **CI и релизы**
  - Makefile (`make ci`, `make test`, `make act-push`, `make act-release`, `make tag-release`).
  - GitHub Actions: проверка на push/PR, автоматический release по тегу `v*`.
  - Скрипты синхронизации версий и извлечения release notes.

### 🔧 Изменено

- **Минимальная версия Home Assistant повышена: 2025.12.5 → 2026.6**
  - Проверка при загрузке интеграции в `async_setup` — на более старых версиях HA компонент не стартует, в лог пишется требуемая версия.
  - Обновлены метаданные HACS (`hacs.json`) и раздел «Требования» в README.
  - Dev/CI переведены на `homeassistant==2026.6.3` и Python 3.14 (требование пакета HA начиная с 2026.6.x).

### 🐛 Исправлено

- **Режим «Паста/Макароны» на RMC-M92S** ([#1](https://github.com/kai-zer-ru/skycooker-ha/issues/1)):
  - вместо «Неизвестно (4)» отображается «Ожидание загрузки продуктов»;
  - кнопка «Старт» после закипания воды снова запускает готовку (только `turn_on`, без повторной отправки программы);
  - время программы показывается корректно на этапе ожидания загрузки продуктов.

## v1.3.2 — 2026-07-28

### ✨ Добавлено

- **Полная поддержка Redmond RMC-M92S (MODEL_6)**
  - Модели `RMC-M92S`, `RMC-M92S-A`, `RMC-M92S-C`, `RMC-M92S-E` переведены в статус полной поддержки.
  - Обновлены таблицы программ `PROGRAM_DATA` и `PROGRAM_NAMES` для 18 режимов (0–17) с подпрограммами.
  - Режим «Ожидание» для M92S вынесен в конец списка программ (отображается в UI, не отправляется на устройство как первая программа).
  - Исправлены параметры по умолчанию для программ MODEL_6 (температура, время, `byte_flag`).

- **Проверка поддерживаемых моделей**
  - Добавлены хелперы `is_model_supported()` и `get_supported_model_names()` в `const.py`.
  - Поддержка вариантов с суффиксом `-E` через базовое имя модели.
  - В `config_flow` при обнаружении Bluetooth показываются только поддерживаемые модели.
  - При попытке добавить неподдерживаемую модель — abort с причиной `unsupported_model` (переводы en/ru).

- **Пример для Яндекс Умного дома**
  - Новый файл `yandex_smart_home_skycooker.yaml`: готовая конфигурация `cooking.multicooker` с режимами, автоподогревом, температурой и скриптами запуска/остановки.

- **Автотесты**
  - Добавлен полный набор unit-тестов: 18 файлов, покрытие config flow, connection, cooking controller, сенсоров, селектов, кнопок, бинарных сенсоров и др.
  - Добавлены `pytest.ini`, `tests/conftest.py`, `tests/README.md`.

- **Брендинг HACS**
  - Иконки и метаданные перенесены в `.github/brands/`.

### 🔧 Изменено

- Версия интеграции в `manifest.json`: **1.3.0 → 1.3.2**.
- Проверка модели при загрузке entry использует `is_model_supported()` вместо прямого обращения к словарю `MODELS`.
- **README.md**: описание расширено на RMC-M92S, упрощена структура (убрано подробное оглавление), обновлена таблица поддерживаемых моделей и раздел «Планы на будущее».
- **SCRIPTS_AND_AUTOMATION.md**: добавлено примечание о зависимости [ha-yandex-station-intents](https://github.com/dext0r/ha-yandex-station-intents) для Yandex.Intents.
- **LOVELACE_UI.md**: убрано оглавление в начале файла.
- **.gitignore**: обновлён список игнорируемых файлов; удалён `.hacsignore` из репозитория.

### ✅ Сохранено из v1.3.1 (без изменений поведения)

Все ключевые доработки предыдущего релиза сохранены:

- Применение настроек на устройство без автозапуска (`apply_current_settings_without_start`) — из селектов и сервисов.

- Автоподогрев на активной программе с fallback на последний известный статус.
- Бинарные сенсоры, диагностика конфигурации, ранняя загрузка переводов, перезагрузка при смене опций.

## v1.3.1 — 2026-03-12

### Что изменилось

- **Применение настроек без автозапуска**
  - Добавлен метод `apply_current_settings_without_start` в контроллер и прокинут через `SkyCookerConnection`.
  - При изменении селектов (`программа/избранное`, `температура`, `время`, `подпрограмма`) настройки отправляются на устройство (`select_program` + `set_main_program`) без `turn_on`.
  - Аналогичное поведение добавлено в сервисы:
    - `set_program`
    - `set_temperature`
    - `set_cook_time`
    - `set_delayed_start`
  - Запуск приготовления по-прежнему выполняется только через `start_cooking`/`run_recipe` или кнопки запуска.

- **Исправлено применение автоподогрева во время работы**
  - Логика `_apply_auto_warm_to_device` теперь применяет флаг автоподогрева для активной программы, а не только при ограниченном наборе статусов.
  - При ошибке чтения актуального статуса используется последний известный статус (fallback), чтобы не терять команду.

- **Улучшен парсинг статуса устройства**
  - Добавлена нормализация полного транспортного кадра статуса `55 <iter> 06 <payload> AA`.
  - Поддержан разбор как "чистого" payload, так и сырого 20-байтного ответа.
  - Для `error_code` добавлен разбор из последнего байта payload статуса.

- **Сенсор звука для MODEL_3**
  - Для `MODEL_3` сенсор `sound_enabled` больше не создается.
  - Логика вынесена в отдельный helper `is_sound_sensor_supported` по аналогии с `is_subprogram_supported`.

- **Документация**
  - Обновлен `SCRIPTS_AND_AUTOMATION.md`: уточнен пример для Умного дома Яндекса и добавлены связанные скрипты запуска/остановки.
